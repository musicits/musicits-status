# 뮤직잇츠 작업 현황 (웹)

로컬 도구 네 개(Tracker · IT 뉴스 모니터링 · 블로그 도구모음 · AI 브리핑 인용 추적)의
결과를 한 장으로 모아 휴대폰에서 보는 페이지입니다.

- `index.html` — 메인. PC 에서 `★_웹에 올리기.bat` 를 누를 때마다 새로 만들어집니다.
- `cloud/` — 휴대폰에서 돌린 결과. 깃허브가 직접 만듭니다.
- `tools/` — 깃허브에서 돌아가는 프로그램들. 이 중 `collect.py`, `blogview.py`,
  `보고서_작성_프롬프트.md`, `blog/` 는 **PC 것의 사본이며 여기서 고치지 않습니다.**
  올릴 때마다 PC 원본으로 덮어씁니다. 고칠 일이 있으면 PC 쪽 원본을 고치세요.

**이 저장소에 직접 파일을 만들거나 고치지 마세요.** 전부 자동으로 만들어집니다.

---

## 처음 한 번만 하는 준비

### 1. 깃허브에 빈 저장소 만들기

github.com 에서 **New repository**.

| 항목 | 값 |
| --- | --- |
| Repository name | `musicits-status` (다른 이름도 됩니다) |
| 공개 범위 | **Public** |
| Add a README file | **체크 해제** |
| .gitignore / license | **None** |

`Create repository` 를 누릅니다. 아무것도 없는 빈 저장소여야 합니다.

### 2. 이 폴더를 그 저장소에 연결하기

PC 에서 `★_웹에 올리기.bat` 를 누르면 알아서 안내합니다.
직접 하고 싶으면 이 폴더에서 명령을 순서대로 칩니다 (`<아이디>` 와 `<저장소이름>` 만 바꿔서):

```bash
git init -b main
git add -A
git commit -m "첫 등록"
git remote add origin https://github.com/<아이디>/<저장소이름>.git
git push -u origin main
```

첫 `push` 에서 브라우저 창이 뜨면 깃허브에 로그인합니다. 한 번만 하면 됩니다.

### 3. 웹으로 보이게 켜기 (GitHub Pages)

저장소의 **Settings → Pages** 로 갑니다.

- Source: **Deploy from a branch**
- Branch: **main** / **/ (root)** → **Save**

1~2분 뒤 주소가 나옵니다: `https://<아이디>.github.io/<저장소이름>/`
그 주소를 휴대폰 브라우저로 열고 홈 화면에 추가해두면 앱처럼 씁니다.

### 4. 휴대폰에서 실행할 수 있게 켜기

저장소의 **Settings → Actions → General** 로 가서 맨 아래
**Workflow permissions** 를 **Read and write permissions** 로 바꾸고 저장합니다.
(결과를 저장소에 다시 써야 하기 때문입니다.)

### 5. 네이버 인증키 넣기 (블로그 도구를 폰에서 돌리려면)

IT 뉴스만 쓸 거면 이 단계는 건너뛰어도 됩니다.

저장소의 **Settings → Secrets and variables → Actions → New repository secret**
에서 네 개를 하나씩 넣습니다. 값은 PC 의 `3_설정/api_key.txt` 에 있는 그대로입니다.

| Name | 값 |
| --- | --- |
| `SEARCH_KEY_ID` | api_key.txt 의 SEARCH_KEY_ID |
| `SEARCH_KEY` | api_key.txt 의 SEARCH_KEY |
| `TREND_KEY_ID` | api_key.txt 의 TREND_KEY_ID |
| `TREND_KEY` | api_key.txt 의 TREND_KEY |

Secret 은 저장한 뒤에는 다시 볼 수 없고, 로그에도 가려져 나옵니다. 실행할 때만
임시 파일로 만들었다가 끝나면 지우며, 그 파일은 `.gitignore` 가 막고 있어서
저장소에 올라가지 않습니다.

### 6. 제목 한국어 번역 (선택)

넣지 않으면 휴대폰 수집 결과가 원문 제목 그대로 나옵니다. 넣으면 한국어 제목과
**주요 이슈 8건 + 왜 중요한지 한 줄**이 목록 맨 위에 붙습니다.

1. [aistudio.google.com/apikey](https://aistudio.google.com/apikey) 에서
   **Create API key** → **새 프로젝트로 만들기**를 고릅니다.
   새 프로젝트로 만들면 무료 한도가 따로 잡히고, 나중에 이 키만 폐기해도
   기존에 쓰던 키에 영향이 없습니다.
2. 받은 키를 저장소 Secret 에 `GEMINI_API_KEY` 라는 이름으로 넣습니다.

**무료 등급을 씁니다. 공짜인 대신 조건이 있습니다** — 구글은 무료 등급으로 보낸
내용을 제품 개선에 쓰고, 사람이 읽어볼 수 있다고 약관에 밝히고 있습니다.
그래서 이쪽으로 보내는 것은 **이미 공개된 기사 제목과 피드 요약뿐**입니다.
블로그 성과 수치나 경쟁 블로그 목록은 절대 보내지 않습니다.
그것도 마음에 걸리면 이 단계를 건너뛰세요 — 번역만 없고 나머지는 그대로 됩니다.

### 7. 휴대폰에서 보고서까지 받기 (선택)

넣지 않으면 휴대폰 수집 결과는 **기사 목록까지만** 나옵니다. 넣으면 PC 와 같은
양식의 보고서(주요 소식 5건 + 요약 + 제목 후보 3개, 나머지는 한줄 목록)가
목록 위에 붙습니다.

집에서는 Claude 가, 밖에서는 Gemini 가 씁니다. 양식 원본은 PC 한 곳
(`1. IT 뉴스 모니터링/3_건드리지마세요/보고서_작성_프롬프트.md`)뿐이고,
`★_웹에 올리기.bat` 을 누를 때마다 `tools/` 로 복사됩니다.

1. 6번과 같은 자리에서 **키를 하나 더** 만듭니다. 여기서도 **새 프로젝트로**
   만드세요.
2. 받은 키를 Secret 에 `GEMINI_REPORT_KEY` 라는 이름으로 넣습니다.

**왜 6번 키를 같이 쓰지 않나** — 보고서는 제목만이 아니라 **기사 본문까지**
넘깁니다. 번역보다 훨씬 크고, 한 키에 묶어두면 보고서가 그날 번역 한도까지
잡아먹습니다. 실제로 기사가 66건 들어온 날 번역이 통째로 빠진 적이 있습니다.
키를 나눠두면 한쪽이 막혀도 다른 쪽은 돕니다.

여기로 가는 것도 **이미 공개된 기사의 제목과 본문뿐**입니다. 6번과 같은 규칙이며,
블로그 성과 수치나 경쟁 블로그 목록은 보내지 않습니다.

키가 없으면 보고서 단계는 스스로 건너뜁니다. 기사 목록은 그대로 나옵니다.

## 평소 쓰는 법

**PC 에서 페이지 갱신** — 맨 위 폴더의 `★_웹에 올리기.bat` 더블클릭.
새 보고서·리포트가 반영되어 올라갑니다.

**휴대폰에서 새 기사 확인** — 페이지 맨 위 `IT 뉴스 수집` 버튼 → `Run workflow`
→ 2~4분 뒤 `cloud/` 에 쌓입니다. `GEMINI_API_KEY` 를 넣어뒀다면 제목이 한국어로
나오고 맨 위에 주요 이슈가 붙습니다. 번역이 어색하면 원문 제목이 바로 아래 작게
같이 나오니 확인할 수 있습니다. `GEMINI_REPORT_KEY` 까지 넣어뒀다면 그 위에
**보고서**가 붙습니다 — PC 보고서와 같은 양식입니다.

**휴대폰에서 블로그 도구 돌리기** — 페이지 맨 위 `블로그 도구 4개` 버튼 →
돌릴 도구를 고르고(`all` 이면 네 개 전부) `Run workflow` → 10~20분 뒤
`cloud/blog/` 에 리포트가 쌓입니다. 엑셀은 만들지 않습니다.

## 알아둘 것

**검색에는 안 잡히지만 공개 페이지입니다.** `robots.txt` 와 `noindex` 로 검색 엔진은
막아뒀습니다. 하지만 주소를 아는 사람은 누구나 볼 수 있습니다. 여기 올라가는 것은
블로그 성과 수치와 경쟁 블로그 목록, 추적 키워드, 그리고 **도구 소스 코드**입니다.
주소를 아무 데나 올리지 마세요.

**AI 브리핑 인용 추적은 클라우드에서 돌리지 않습니다.** 그 도구는 네이버 검색 화면을
브라우저로 훑는 방식이라 데이터센터에서 돌리면 캡차·차단에 걸리기 쉽고, 도구 자체가
'우회 시도 없음'을 원칙으로 두고 있습니다. 그건 PC 에서만 돌립니다.

**비밀값은 올라가지 않습니다.** 네이버 API 키는 `3_설정/api_key.txt` 에만 있고 이
저장소에는 들어오지 않습니다. 페이지를 만들 때마다 키가 섞였는지 한 번 더 검사하고,
섞였으면 올리지 않고 멈춥니다.

**휴대폰 수집과 PC 수집은 기록이 따로입니다.** 휴대폰에서 본 기사도 PC 에서 보고서를
만들 때 다시 나옵니다. 반대도 마찬가지입니다. 한쪽에서 돌렸다고 다른 쪽 기사가
사라지지는 않으니, 빠뜨릴 걱정은 하지 않아도 됩니다.

**휴대폰에서는 보고서를 쓸 수 없습니다.** 요약·제목 후보는 Claude 가 원문을 읽고
쓰는 것이라 PC 에서만 만들어집니다. 휴대폰 쪽은 기사 목록까지입니다.
